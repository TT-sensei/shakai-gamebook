# 社会科ゲームブック

「読む → 考える → 選ぶ → 結果を見る」を軸にした社会科の学習ゲームブック。

現在は「米づくり」と「自動車づくり」を収録しています。

## 構造

- `index.html` — 社会科ゲームブックの入口。
- `kome-zukuri.html` — 米づくりゲームの入口。
- `jidosha-zukuri.html` — 自動車づくりゲームの入口。
- `data/kome-zukuri.js` — 米づくり固有のシナリオデータ。
- `data/jidosha-zukuri.js` — 自動車づくり固有のシナリオ・工程・突発イベント。
- `js/gamebook-engine.js` — 単元に依存しない共通ゲームエンジン。
- `js/jidosha-ui.js` — 自動車づくり専用の工程確認UI。
- `css/style.css` — 共通UI。

## 自動車づくり版の設計

自動車づくり版は、工場の生産工程を中心に、企画から出荷までを一本の流れとして体験できる構成にしています。

基本の流れは、

「企画 → プレス → 溶接 → 塗装 → 組立 → 検査 → 出荷」

です。

ゲーム中は現在の工程を画面上で確認でき、いつでも「工程を確認」を開いて、

- いまどの工程にいるか
- 終わった工程
- このあと何をするか
- 各工程の主な仕事

を確認できます。

工場工程は、トヨタ自動車の公式「トヨタバーチャル工場見学」などを参考に、子どもが工程のつながりを理解しやすいように一般化して構成しています。

## 自動車づくりで扱う学習内容

- 企画と使う人・社会の変化
- 多くの会社による分業と協力
- プレスによる鋼板の加工
- 溶接による車体づくり
- 塗装と品質管理
- 組立と部品供給
- 人と機械の役割分担
- 工程の中で品質を確認する仕組み
- 異常があったときにラインを止めて確認する考え方
- 環境への配慮と生産効率
- 最終検査
- 完成車の輸送
- 国内外の市場とのつながり
- 他のメーカーとの競争の中での改善

## 突発イベント

プレイごとに一部の突発イベントが入ります。

主なテーマは、

- 部品の到着遅れ
- 工程の異常
- 現場からの改善案
- 環境への工夫
- ほかのメーカーとの競争

です。

突発イベントは単なるゲーム上の障害ではなく、「分業」「効率化」「品質」「安全」「環境」「競争」などを考える場面として使用します。

特に「速くつくること」と「品質・安全を守ること」が単純な正解にならないよう、選択によって別の影響が生まれる設計にしています。

## 参考資料

自動車づくりの工程・工夫を設計する際には、主に以下の公式資料を参考にしています。

- トヨタ自動車「クルマをつくる工場を見てみよう」
- トヨタ自動車「クルマづくりのくふう」
- トヨタ自動車「トヨタバーチャル工場見学」
- トヨタ自動車「よくわかる『トヨタ生産方式』」
- 三菱自動車「工場見学・バーチャル工場見学」

ゲーム内の文章は、特定企業の教材をそのまま転載するのではなく、社会科の学習用に一般化・再構成しています。

## ゲームの基本設計

社会科の知識をクイズとして当てるのではなく、社会の中で起こる状況を読み、自分で判断し、その選択によって何が変わるかを体験します。

基本の流れは、

「状況を読む → 考える → 選ぶ → 結果を見る → 次の判断へ」

です。

各単元には、必ず扱う「核となる学習内容」と、プレイごとに変化する「突発イベント」を設定します。

## 設計原則

- GitHub Pagesで動作する静的HTML/CSS/JavaScript
- APIキー・バックエンド不要
- シナリオとゲームエンジンを分離
- edu-kitのタブレットファースト、読みやすさ、共通UIの考え方を活用
- 問題・選択・結果を優先し、装飾やゲーム要素が学習を邪魔しない
- 「正解・不正解」よりも、選択による結果と振り返りを重視
- 状態の変化によって判断の結果を見える化
- 突発イベントによって同じ単元を複数回体験できる
- 必須学習内容は突発イベントによって省略しない
- 単元固有の教育内容はデータ側に置き、エンジン側に書き込まない
- 教室で20〜25分程度で1プレイできる構成を基本とする

## 画像・外部素材

外部素材を利用する場合は、

- 教育的に有効であること
- 利用条件が明確であること
- ライセンスを確認できること
- 必要に応じて出典・作者を画面上に表示すること

を基本とします。
