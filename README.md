# 社会科ゲームブック

「読む → 考える → 選ぶ → 結果を見る」を軸にした社会科の学習ゲームブック。

現在は「米づくり」を収録しています。

## 構造

- `index.html` — 社会科ゲームブックの入口。今後の教材を追加するハブ。
- `kome-zukuri.html` — 米づくりゲームのエントリーポイント。
- `data/kome-zukuri.js` — 米づくり固有のシナリオ・必須学習内容・突発イベント・画像情報。
- `js/gamebook-engine.js` — 単元に依存しない共通ゲームエンジン。
- `css/style.css` — 共通UI。

## 拡張方針

新しい単元は、基本的に「シナリオデータ」を追加して共通エンジンを再利用します。

例：
- `data/jidosha-zukuri.js`
- `data/news-zukuri.js`

入口の `index.html` から各ゲームを選べる構造にしていきます。

## ゲームの基本設計

社会科の知識をクイズとして当てるのではなく、社会の中で起こる状況を読み、自分で判断し、その選択によって何が変わるかを体験する。

基本の流れは、

「状況を読む → 考える → 選ぶ → 結果を見る → 次の判断へ」

です。

各単元には、必ず扱う「核となる学習内容」と、プレイごとに変化する「突発イベント」を設定します。突発イベントは学習内容を飛ばすためではなく、同じ単元を繰り返し体験したときの展開に変化をつけるために使用します。

## 米づくりの状態システム

米づくりでは、最初に5つの状態をすべて「3」から開始します。

- 水管理 💧
- 稲の育ち 🌾
- 作業効率 ⚙️
- 地域との協力 🤝
- 米の品質 📦

選択によって状態が上下します。状態は0〜5の範囲で管理します。

特に、機械を使わずに人手で行う選択では、作業効率が下がることがあります。一方で、機械を使えば必ずすべてがよくなるという設計にはせず、効率・自然・品質・協力などの間にトレードオフが生まれるようにします。

どれか1つの状態が0になった場合、その年の米づくりは失敗となり「ゲームオーバー」です。

ゲームオーバーは単なる罰ではなく、「どの状態が0になったのか」「それまでにどんな判断をしたのか」を振り返るための学習材料として扱います。

## 状態変化の表示

選択後の結果画面では「今回の変化」を表示します。

例：

- 🌾 稲の育ち ＋1
- 💧 水管理 −1
- ⚙️ 作業効率 ＋1

これにより、選択と結果のつながりを児童が画面上で確認できるようにします。

ゲームオーバー時には、0になった状態と5つの最終状態を表示し、最後に振り返りを書けるようにします。

クリア時にも「一年間の結果」として5つの状態を表示します。これは総合点やランキングではなく、それぞれの判断が一年間の米づくりにどのような影響を与えたかを振り返るための状態表示です。

## 学習内容とゲーム性

ゲーム性を高めつつ、社会科の学習内容を中心にします。

米づくりでは、例えば以下を扱います。

- 苗づくり
- 田起こし・代かき
- 田植え
- 水管理
- 稲の成長観察
- 収穫時期の判断
- 稲刈り
- 乾燥・もみすり
- 出荷
- 自然条件への対応
- 機械や技術の活用
- 地域との協力

「正解を選ぶ」だけではなく、効率を上げると別のことに影響したり、時間をかけることで品質や協力を大切にできたりするような判断を入れます。

## 画像・外部素材

ゲーム内では、学習場面を具体的にイメージできる写真を使用します。

外部素材を利用する場合は、

- 教育的に有効であること
- 利用条件が明確であること
- ライセンスを確認できること
- 必要に応じて出典・作者を画面上に表示すること

を基本とします。

米づくりの写真は、Wikimedia Commons等のライセンスを確認した素材を使用し、ゲーム内に出典・ライセンス確認用のリンクを表示しています。表示用画像は読み込み負荷を抑えるため幅800px指定のURLを基本とします。

## 設計原則

- GitHub Pagesで動作する静的HTML/CSS/JavaScript
- APIキー・バックエンド不要
- シナリオとゲームエンジンを分離
- edu-kitのタブレットファースト、読みやすさ、共通UIの考え方を活用
- 問題・選択・結果を優先し、装飾やゲーム要素が学習を邪魔しない
- 「正解・不正解」よりも、選択による結果と振り返りを重視
- 状態の変化によって判断の結果を見える化する
- 状態が0になった場合はゲームオーバーとする
- 突発イベントによって同じ単元を複数回体験できる
- 必須学習内容は突発イベントによって省略しない
- 単元固有の教育内容はデータ側に置き、エンジン側に書き込まない
- 教室で20〜25分程度で1プレイできる構成を基本とする

## 現在の状態

米づくり版は、ゲームの基本ループ、突発イベント、ナビキャラクター、場面写真、5種類の状態管理、選択による状態変化、結果表示、ゲームオーバー、振り返りまで実装済みです。

今後は、各選択肢に設定する状態変化をより具体的な米づくりの判断に合わせて調整し、特に「機械を使う／使わない」「効率を優先する／丁寧さを優先する」「個人で進める／地域と協力する」といったトレードオフを明確にしていきます。
